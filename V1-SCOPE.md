# ITD EXTENDED — v1 (согласованный скоуп)

Дата: 17.10.2026. Проект: `itd-ext v3`. Проверено на живой сессии: API `notifications/*`, `users/me`, `users/:id/followers|following`; авторизация — Bearer-JWT (~15 минут), которым ходит сам сайт. Статус: все фичи v1 проверены сквозным тестом (Chrome + расширение, загруженное распакованным).

## Фичи v1

1. **Хранитель непрочитанных + бейдж** (идеи 1 и 38).
   Фоновый опрос `notifications/count` и списка: счётчик на иконке, список «Пропущено» — не теряется, когда сайт сбрасывает уведомления в прочитанные.
2. **Системные уведомления** (идея 2).
   Windows-всплывашки о лайках/комментах/подписках, пока открыта хотя бы одна вкладка итд.com.
3. **Локальная аналитика** (новая + идея 40).
   По дням: лайки, комментарии, новые подписчики; чипы «сегодня» + график за 14 дней.
4. **Дифф подписок** (идея 9).
   Раз в день сохраняются списки подписчиков/подписок: «кто пришёл / кто ушёл» с именами, история 60 дней.
5. **Счётчик постов и полные числа на профиле** (новая).
   На своём и чужом профиле рядом с «подписчиков/подписок» добавляется «N постов» (поле `postsCount` из API профиля; контейнер статистики получает перенос строки, чтобы ничего не перекрывалось). Сокращённые сайтом числа («1.6K») заменяются полными значениями из API — подписчики, подписки и посты.
6. **Кнопка «ITD EXTENDED» в левом меню после «Профиль»** (новая).
   Нативный пункт меню (клон стиля сайта) → панель расширения: вкл/выкл фич, экспорт и очистка данных.
7. **Свой бренд на сайте** (новая).
   Логотип в боковом меню заменяется на кастомный «ITD EXTENDED» (рамка с «и» + вордмарк), кнопка версии показывает версию расширения, список изменений платформы подменяется нашим (перехват ответа `/api/platform/changelog` в MAIN-мире), иконка вкладки — тоже ITD EXTENDED.

## Механика

- **Токен**: расширение никогда не вызывает `auth/refresh` само. Refresh-кука сайта ротируется, и параллельный refresh сжигал сессию (проверено на живом аккаунте) — поэтому Bearer-токен перехватывается у самого сайта через `chrome.webRequest.onBeforeSendHeaders` (с `extraHeaders`) и живёт в `chrome.storage.session`.
- **Опрос**: контент-скрипт на открытой вкладке раз в минуту (и при возврате на вкладку) пингует service worker — это гарантированно его будит, потому что события `webRequest` спящий воркер не поднимают. Из ответа берётся перехваченный токен (свежесть проверяется по `exp` из JWT), и запросы `count` + список уведомлений идут same-origin fetch'ем со страницы, как это делает сам сайт. Результаты отправляются воркеру одним сообщением: он хранит данные, считает бейдж и показывает уведомления. Раз в 10 минут дополнительно обновляется профиль; раз в ~20 часов — снапшоты списков подписчиков/подписок (базовый снимок → дальше диффы).
- **Данные** — только в `chrome.storage.local` (никаких внешних серверов): `notifIndex` (до 2000 записей), `daily`, `snapshots`, `followLists`, `followDiff`, `me`.

## Ограничения и компромиссы

- Опрос идёт, только пока открыта хотя бы одна вкладка итд.com: токен появляется лишь из запросов самого сайта. Закрыл все вкладки — расширение молчит до следующего открытия.
- Хаки CSS-классов сайта не используются: внедрение по тексту/href, стили клонируются у нативных элементов. Релиз сайта может сломать — есть защита «не нашёл — не трогаю».
- На непрофильных страницах счётчик постов не появляется (там нет блока «подписок»).
